DebugBrief/Docs

command reference

Run the loop.
Keep the proof.

DebugBrief is deliberately small: run a command, record what you noticed, repeat it after a change, and end with a report. This page is the fast reference.

01

Quickstart

Start is optional. The first run or note starts a session automatically.

shell
pipx install debugbrief
debugbrief run -- pytest -q test_calc.py
# make the fix
debugbrief redo
debugbrief end --format html --open
today's loop

The command stays yours. DebugBrief records the command, exit code, duration, bounded output preview, and Git state when available.

02

Install

Python 3.9 or newer. Linux and macOS are tested. The project you are debugging does not need to be Python.

pipx install debugbriefrecommended for a standalone CLI
uv tool install debugbriefif you use uv tools
python -m pip install debugbriefinside an existing environment
03

run

Put DebugBrief flags before --, then the command exactly as you would normally type it.

shell
debugbrief run -- pytest -q
--timeout SECONDSstop a long-running command
--verifydeclare a custom check
--shellenable pipes and redirection
--no-redactstore raw output, with care
04

note

Record an observation without interrupting the loop. Quoting is optional for plain prose.

shell
debugbrief note "the shared state is the suspect"
05

redo

Re-run the latest captured command in its original directory. It is the shortest path from a failing check to a passing check.

shell
debugbrief redo
safe replay

--dry-run previews without executing. Ambiguous or destructive commands ask for confirmation; --yes is an explicit bypass.

06

Checks and verification

Recognized test, build, lint, and typecheck runners are classified automatically. A check is verified only when its real exit code is zero. Use --verify for a custom script.

pytestvitestgo testcargo testmake checknpm run buildtsc --noEmitdotnet test
07

end

Finalize the session and write the selected report. PR reports are compact by default; --detail full keeps the complete record.

shell
debugbrief end --mode pr
debugbrief end --mode handoff
debugbrief end --mode incident
08

Report modes

PRReproduce, verify, red → green, files, failures.
HandoffCurrent state, notes, timeline, next steps.
IncidentTime window, observed error, resolution, follow-up.
09

Output formats

--format mddefault Markdown brief
--format jsonstructured evidence
--format bothMarkdown and JSON artifacts
--format htmlself-contained browser report
--format allall three artifacts

Every report exposes an explicit verified or unverified state and says when a root cause was not inferred.

10

Review and share

After end, the proof is local. Inspect the artifact before sending it anywhere. preview --format html lets you inspect the same self-contained view before finalizing.

shell
debugbrief end --format html --open
debugbrief open --html
debugbrief last --open

open --html selects the newest HTML brief explicitly. HTML artifacts also open in the system browser automatically; non-HTML reports open in $EDITOR.

11

status and recovery

status shows the active session and any running captured command. If a process crashes, recover repairs stale state without deleting the session.

shell
debugbrief status
debugbrief doctor --fix
debugbrief recover
12

Privacy and redaction

Reports hide the absolute project root by default and show the repository basename. Pass --include-full-path only when the full local path is intentional.

Commands, output previews, titles, and notes pass through conservative redaction before persistence. Review every report before sharing it.

13

Limitations

  • No full-screen TUI capture such as vim or htop.
  • No passive shell-history capture.
  • No guaranteed secret detection.
  • No native Windows or PowerShell support.
  • No inferred root cause.
